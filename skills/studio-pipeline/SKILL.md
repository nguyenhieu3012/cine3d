# studio-pipeline

## What the system is
- Two channels, one engine (`~/cine3d`), one tool: `python3 ~/cine3d/tools/pipeline.py` (`pipeline.py`).
- Per episode: `~/cine3d/episodes/<id>.{card.json,treatment.md,beats.json,js}`; outputs `out/<id>/`.
- DONE only when a file or a recorded verdict proves it.
- Read next: `driver.md`. Vault `08 Assistant System/`: `chuan-dien-anh-v4 (13-11).md`, `production-workflow-v4 (13-11).md`. Checks: `ENGINE.md` "Machine checks v4", `docs/v4-*.md` (in `~/cine3d`).

## Start here
1. `pipeline.py list`. New: `new <id> --channel trada|goat`; begun before the tool: `adopt <id> --channel <X>`; remake: `copy <src-id> <new-id>` (never edit an approved episode). Owner-decided points go in the card's `owner_fixed` list: gates may note them, not reopen them.
2. `status <id>` (`--run` runs the checks), then `next <id>`: what, who, model+effort, command, brief template. `brief <id> <template>` prints a template from `~/cine3d/pipeline/briefs/`; fill each `<...>`.
3. Verdicts no file proves (script_gate, facts, driver_review, render, episode_gate, owner, posted): `record <id> <step> pass|fail --by <who> [--note --quote --mp4 --platform --video-id]`.
4. Read `channels/<channel>.md`, then that channel's state file.

## Laws (both channels)
1. Cheap gates first: weak idea dies at the card, weak script before voice credit, flawed sheet before the full render.
2. Machines measure, agents judge, you direct. Trà đá: every message that sends a test or Final to the owner ends with the 6-door PASS table of unified Blueprint Part 6 (hook and opening, UI logic and clues, acting/comedy/set, pace and trimming, ending and 10K, final hygiene and audio); a failed door is fixed first and the cut is never sent. Never send the owner a cut with a known flaw; say in one line what nobody heard or watched at speed.
3. Never loosen a check or rename a shot to pass it. An exception = a waiver with a reason in the episode or beats file (`waive`, `marginWaive`). A check you think wrong: report it.
5. Every Agent call sets `model` and `effort` (`driver.md`); name them in parentheses when you mention an agent to the owner. A sub-agent cannot spawn agents: do those steps inline.
6. Nothing is posted unless `can-post <id>` exits 0 and the owner said yes in his own words for that post; if ordered otherwise: "chưa qua cổng", stop. Only the sharp 30 fps (CFR, CRF 17, AAC 192k 48 kHz) 1080x1920 file goes up; never a low-bitrate copy (the owner 23/11/2026 made 30 fps the official standard; films already posted at 60 fps stay valid).
8. A NEW idea: once the card is chosen, send the owner three lines (title, first frame on screen, logline) as information and carry on without waiting; his correction goes into the card's `owner_fixed` before any voice credit. Trà đá is an ANTHOLOGY from 26/11 (unified Blueprint 23/11, Part 3; Zombie shelved): no new serial that needs earlier parts after 25/11; a series rule below applies to GOAT Beef and to a Trà đá series the owner names. A SERIES (card kind `series:<name>`): first write the spine file (one line per part, the ending, and the world rule "who knows the hero, and from where"), send it, and WAIT for one word from the owner before any script is written. One script at a time: part N+1 is written after the owner has seen part N (20/11: four scripts were written and gated first, three then changed, about 2M tokens redone). The writer, the script gate and the builder read the spine.
9. Needs the owner's yes: credit above the ceiling; posting or scheduling; deleting, unscheduling or editing a published post; replying or messaging; account or channel settings; an approved-look change (`regress.py --save`); a music library (quote the price); GitHub releases.
10. An episode posted the same day uses only assets that exist and are signed off (sets, characters, poses, props, overlays, and their look2 lighting). Anything new needs a day of buffer; when the owner sets a deadline that needs new assets, say at once what must be cut. Times written in notes come from `date`, never from memory.
11. Spawning costs, resuming is cheap (measured 20/11): an agent with no `tools:` list starts at ~95K tokens, one with a short list at ~18K, a resume by SendMessage adds 2-10K. So: no agent for a one-command job; never `general-purpose` for work a listed agent can do; give every agent file a `tools:` list; send follow-ups to the same agent. Limit (measured 21/11): a resume is cheap only while that agent is under about 150K and was active in the last hour; past that, start a fresh agent on `out/<id>/handover.md`. The build runs in stages (A data + checks, B fixes, C render), one hand-over file per stage. Engine or renderer work (new sets, Blender, a new channel) is cut into stages of at most about 150 turns, each with its own agent and hand-over; never one agent for the whole job. Briefs say: several commands in one script, waits by background run, no `sleep` or polling, output through `tail`.

## When stuck
- A check fails: fix the episode, not the tool.
- The engine lacks something ("Not in cine3d yet" in `~/cine3d/ENGINE.md`): stop and follow "Extending the engine without breaking it" there (look test, stills, qa, `regress.py` PASS, document).
- STALE: a file changed after its verdict. Re-run the check; re-ask the gate only the changes.
- No owner answer yet: do what does not depend on it; list it under "waits for the owner" in the state file.

## Hand-over
Overwrite the channel's state file: date; per episode (id, step, waiting on whom); what waits for the owner; next three actions; pointers. Under 4 KB, no history: cut text goes to `STATE-history.md` beside it, newest first. Also 3-6 lines in the script doc's log ("Nhật ký chấm"), one line in the channel's episode list.
